# 先导杯校内赛：二维地震断层分割推理优化

## 一、赛题背景
作为我国第二所创建的石油本科院校，西南石油大学在石油与天然气工程领域积淀深厚。石油天然气勘探需要经历一系列复杂的前期准备，地质勘探作为其中的关键一环，需要面对地下构造无法直接观测、强随机噪声干扰及深层信号衰减等难题。其中，断层是控制油气运移与成藏的核心构造，其空间几何位置的精准识别直接决定了地质建模的成败。然而，面对指数级增长的海量地震资料与模糊的断层边界，传统依赖人工判读地震剖面同相轴特征的模式，耗时费力且易受主观经验制约，已难以满足现代高效勘探的现实需求。
深度学习通过将断层识别转化为图像语义分割任务，为自动拾取提供了全新范式。但该技术的规模化落地仍面临识别精度与计算效率的双重瓶颈：既要精准表征复杂微小的断层拓扑以避免漏检与轨迹断裂，又要满足海量剖面连续批处理的低延迟、高吞吐要求。为此，本赛题以“二维地震断层语义分割”为核心任务，基于 U-Net 基准程序与国产深度计算单元（DCU）算力平台，要求参赛者结合算法特征与国产硬件架构进行协同优化，探索兼顾高分割精度与高吞吐效率的技术方案。

## 二、赛题任务
本赛题提供基于 PyTorch 的 U-Net 地震断层分割基准程序、预训练权重及公开数据集，要求参赛者在指定的国产 DCU 算力环境下开展模型与推理流程的优化工作。
赛题的核心目标是对模型的预测精度与端到端运行时间进行协同优化：参赛者需在保持或提升断层识别精度的同时，最大限度地缩短程序运行耗时，探索分割精度与计算效率的最佳平衡。
参赛团队须提交可独立运行的推理源码与技术报告。最终成绩由运行耗时、分割精度及技术报告综合评定。

## 三、基线初始运行

基线训练、评估、预测及提交模板默认使用PyTorch原生卷积（`torch`后端），不编译或调用自定义HIP Kernel。自定义Kernel为可选开发示例，使用方法见第八节。

运行环境为Linux x86_64、Python 3.11、GCC 12.2.0及DTK 25.04.2。请在参考代码包根目录安装以下依赖：

```bash
# 安装DCU适配PyTorch、NumPy和Matplotlib
python -m pip install \
  'https://download.sourcefind.cn:65024/file/4/pytorch/DAS1.7/torch-2.7.1+das.opt1.dtk25042-cp311-cp311-manylinux_2_28_x86_64.whl' \
  -r requirements.txt

# 仅编译自定义HIP示例时需要
python -m pip install ninja==1.13.0
```

```bash
# 1. 在登录节点申请交互式计算资源（仅为开发申请示例）
srun --partition=hx1hdnormal --nodes=1 --ntasks=1 \
  --cpus-per-task=4 --gres=dcu:1 --mem=14G \
  --time=00:20:00 --pty bash

# 2. 在分配的计算节点中加载公共工具链
module load compiler/gcc/12.2.0 compiler/dtk/25.04.2
export OMP_NUM_THREADS=4 MKL_NUM_THREADS=4

# 3. 检查环境（DCU沿用PyTorch的cuda设备标识）
python -c 'import torch; print("PyTorch:", torch.__version__, "HIP:", torch.version.hip); assert torch.version.hip and torch.cuda.is_available(), "DCU不可用"; print("Device:", torch.cuda.get_device_name(0))'

# 4. 直接使用附带权重验证公开验证集，无需先训练
python src/main.py evaluate --checkpoint weights/baseline.pt \
  --data-dir data --backend torch --device cuda --output outputs/my-evaluation

# 5. 按需重新训练基线（默认50轮；输出目录须为新目录）
python src/main.py train --config configs/baseline.json \
  --device cuda --output-dir outputs/my-baseline
```

训练与推理须在分配的计算节点内执行。公开数据位于`data/`，参考配置划分为1,280张训练、320张验证。

训练日志格式示例：

```text

```

关键输出如下：

```text
outputs/my-baseline/
  last.pt                  # 最后一轮权重
  best.pt                  # 验证BCE最低的权重
  history.json             # 每轮训练与验证指标

outputs/my-evaluation/

```

验证Dice见`metrics.json`的`metrics["0.5"]["dice"]`。正式计时规则见第五节。参考权重统一存放于`weights/baseline.pt`，提交模板不重复存储模型文件。生成基线推理包：

```bash
python scripts/package_submission.py --source submission_template \
  --reference --output submission.zip
```

打包时自动收集参考模型与权重，生成的ZIP可独立运行。训练后的U-Net权重可通过`--checkpoint outputs/my-baseline/last.pt`指定。更换模型时，将必要代码与权重放入`submission_template/submission/`并修改入口，打包时不使用`--reference`。

## 五、评测过程与结果格式

公开数据集共1,600张，训练与验证划分由参赛者自行确定。赛中评测从公开数据中预先抽取并固定400张，所有提交使用同一批样本，反馈运行时间和Dice，仅供调试与性能参考，不计入最终成绩；这些样本仍可用于训练，赛中Dice不代表隐藏集表现。

最终定榜使用另外400张未公开的隐藏数据。参赛者须在截止前指定一个最终提交，截止后冻结代码、权重及推理参数；隐藏集结果在冻结前不予反馈，最终成绩仅依据冻结提交的隐藏集评测与技术报告计算。赛中和最终评测均须实际执行推理，禁止缓存预测答案。

提交程序须满足以下评测要求：

1. 在规定的隔离环境中完成全部400张测试图像的推理，输出第四节规定的预测文件。
2. 从程序启动至结果写完并退出全程计时，初始化、运行时编译、输入输出及预后处理均计入；无免计时预热。
3. 精度依据预测文件与对应标签计算，指标计算不计入程序耗时；无需自行输出Dice。
4. 相同提交以新进程运行3次，时间和Dice分别取算术平均；**任意一次异常退出，本次提交整体成绩为0**。

\[
T=\frac{T_1+T_2+T_3}{3},\qquad Q=\frac{Q_1+Q_2+Q_3}{3}.
\]

每次Dice按全部测试图片累计计算：

\[
Q_i=\frac{2TP_i}{2TP_i+FP_i+FN_i}.
\]

TP、FP、FN分别为正确检出、误报和漏检像素数。空图预测正确不额外加分，误报计入FP。

## 六、分数构成与公式

| 分项 | 满分 | 内容 |
| --- | ---: | --- |
| 时间分 \(S_t\) | 50 | 完整程序相对精度达标最优提交的耗时 |
| 精度项 \(F(Q)\) | 40 | Dice低于0.4时附加扣分，最低−50分 |
| 设计答辩分 \(S_d\) | 10 | 模型、算法、算子或系统优化设计与证据 |

评分按时间、精度、设计答辩5:4:1计分，公式如下。\(t\)、\(Q\)分别为三次运行的平均耗时与Dice；\(T_*\)为包含基线在内、Dice不低于0.4的有效提交最短平均耗时，\(Q_*\)为包含基线在内的有效提交最高平均Dice。最终成绩在全部冻结提交评测完成后统一计算。

\[
S_t=\frac{50}{1+\log_{1.5}\!\left(\max\left(1,\frac{t}{T_*}\right)\right)},\qquad
A(Q)=\frac{40}{1+\log_{1.5}\!\left(\max\left(1,\frac{Q_*}{Q}\right)\right)}\quad(Q>0),\qquad A(0)=0.
\]

时间项和正常精度项均采用底数为1.5的非线性对数比值形式。时间与精度参考均使用同一400张隐藏集、同一正式评测条件下的结果，不沿用赛中公开样本结果。精度低于0.4的提交不更新时间参考。基线分数按同一公式计算。

总分与精度惩罚：

\[
S=S_t+F(Q)+S_d,\qquad 0\le S_d\le10,\qquad
F(Q)=\begin{cases}
A(Q),&Q\ge0.4,\\[2mm]
A(Q)-50\left(1-\dfrac{Q}{0.4}\right),&0\le Q<0.4.
\end{cases}
\]

精度阈值为0.4，精度项最低−50分。低于阈值时按上式附加线性扣分，精度项在阈值处连续，Dice为0时为−50分；惩罚仅作用于精度项。总分按上式直接相加，不另作截断。

设计答辩评价模型、算子或系统优化的设计依据与实验结果，具体评分表与同分排序规则另行公告。

## 七、优化限制

- 禁止使用隐藏数据、额外上游数据及其他外部数据进行训练、微调、校准或选参；禁止使用外部数据训练的预训练权重、教师模型及模型服务，或通过伪标签绕过数据来源限制。
- 禁止在测试过程中训练或自适应更新权重、BN统计、校准参数等持久状态。
- 禁止缓存预测答案、按样本身份查表返回结果，或跨正式运行保留进程及输入特征以绕过实际计算。
- 禁止修改固定评测代码、读取私有标签、访问未授权文件、调用额外加速卡或外部网络服务，以及超出分配资源。
- 禁止根据评测阶段切换权重、配置和推理路径以分别获取精度与时间成绩。
- 禁止改变输出的样本对应关系、空间尺寸或坐标含义；不得以概率图或其他格式替代规定的二值掩码。
- 不得提交无法在正式DCU环境运行的程序，或缺少训练及产物生成复现材料的方案。

资源暂定为4个物理CPU核、16 GiB主机内存和指定单张DCU；正式型号、工具链、显存及空间配额须经实测冻结后公告。

## 八、Baseline代码结构与自定义Kernel

基线采用PyTorch U-Net，包含三级下采样、最近邻上采样及跳跃连接，共15层卷积、487,009个参数。模型输出logits，推理时经Sigmoid和阈值处理生成二值掩码。训练与默认推理均使用PyTorch原生卷积。

| 文件或目录 | 作用 |
| --- | --- |
| `src/main.py` | 训练、评估、预测与性能对照的命令入口 |
| `src/model.py` | U-Net网络结构 |
| `src/data.py` | 数据加载、划分和逐图标准化 |
| `src/engine.py` | 训练、验证及预测流程 |
| `src/ops.py` | 可替换卷积层、后端注册及HIP扩展加载 |
| `src/utils.py`、`src/benchmark.py` | 指标与可视化等辅助功能、开发性能对照 |
| `src/csrc/` | pybind11绑定、HIP源码与自定义Kernel指南 |
| `configs/`、`data/`、`weights/` | 训练配置、公开数据和参考权重 |
| `submission_template/`、`scripts/` | 固定提交入口、打包与接口检查工具 |

U-Net中的卷积统一经过`src/ops.py`调用后端实现。选择`torch`时执行原生卷积；选择`hip`时通过pybind11调用自定义HIP Kernel，两者复用同一份模型权重。默认基线不编译或执行HIP示例。

自定义Kernel的修改位置、接口要求、验证命令和提交方式见[自定义Kernel示例指南](src/csrc/README.md)。该示例用于说明接入流程，不保证加速；开发性能测试仅用于优化对照，比赛时间成绩以固定评测程序测得的完整运行耗时为准。
